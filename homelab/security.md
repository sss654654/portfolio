클러스터가 개발 PC와 같은 사설망에 있었습니다. 인터넷에 여는 순간 그 평면 전체가 표면이 되므로,
열기 전에 경계부터 세웠습니다.

## 격리와 공개 구조

<!-- TODO 구조도 — 카드1·3의 hl-diagram 형식(인라인 SVG)으로 다시 그린다.
     담을 것 셋:
       공개 경로   방문자 → Cloudflare → 공유기(443/TCP) → OPNsense → Traefik → 앱

       ✕ 경로     공인 IP:443 직접 → OPNsense 가 버린다 (출발지가 엣지 대역이 아님)

```
공개 경로 — 누구나

  방문자 ──► Cloudflare ──► 공유기 ──► OPNsense ──► Traefik ──► frontend · queue · booking
             엣지          443/TCP    → 10.0.0.240      경로대로

  ✕  공인 IP : 443 으로 직접 ──► OPNsense 가 버린다 (출발지가 엣지 대역이 아니다)


관리 경로 — 등록된 키를 가진 기기 둘

  관리자 ──► 공유기 ──► WireGuard @ OPNsense ──► 격리망  Grafana · ArgoCD · k8s API
            51820/UDP                            443 으로는 안 열려 있다

  └────────────── 전부 노트북 1대 · Proxmox 위, 격리망은 물리 포트 없는 가상 스위치 ──────────────┘
```

문이 둘이고 성격이 정반대입니다. **정문은 넓게 알리고 좁게 열고**(443 하나, 그것도 엣지를 지난 것만),
**뒷문은 숨기고 강하게 인증합니다**(등록된 키가 아니면 응답 자체가 없습니다).

## 정한 것

| 무엇을 | 고른 것 | 그렇게 한 이유 |
|---|---|---|
| 격리 방식 | **OPNsense 방화벽 VM + 물리 포트 없는 가상 스위치** | **노드와 개발 PC가 한 평면에 있었음**<br>뚫린 파드가 GitLab·kubeconfig·레지스트리에 그대로 닿는다. 그 자격이 새면 GitOps 재현 자체가 조종당한다 — 평면을 계층으로 |
| 관리 접근 | **WireGuard** (OpenVPN 아님) | **여기가 뚫리면 격리 전체가 무효**<br>코드 약 4천 줄이라 사람이 훑을 수 있는 크기. 등록 안 된 키에 한 바이트도 응답하지 않는 것이 설정이 아니라 프로토콜 기본 |
| 엣지 | **Cloudflare 프록시** | **집 공인 IP 은닉 + 연결을 앞에서 종료**<br>대기자가 폴링하는 동안 traefik 이 연결을 계속 들어 인원에 비례해 쌓인다. 엣지가 그 연결을 대신 받는다 |
| 이름 | 한 도메인, **`ticket` 은 프록시 켬 · `vpn` 은 끔** | **프록시가 중계하는 것은 HTTP·HTTPS 뿐**<br>WireGuard 는 UDP 라 켤 수 없다. 같은 도메인에서 한쪽만 가려진다 |
| 남용 방지 | **앱 rate limit 안 넣음** | **몰리라고 만든 서비스**<br>요청 수로 보면 정상(1만 명이 한 번씩)·부하(한 대에서 1만 번)·남용이 같은 모양이다. 재는 축이 달라 값을 어떻게 잡아도 안 맞는다 — 좌석 오염은 주기 초기화가, 대량 트래픽은 엣지가 받는다 |
| 클러스터 안 | **NetworkPolicy 16줄 · 읽기 전용 자격 · DB 전용 계정** | **경계를 세워도 안은 평평**<br>파드 하나가 잡히면 관측 스택·MinIO·Kafka 로 그대로 간다. 정책은 허용만 적을 수 있어 통로를 전수로 세야 한다 |
{:.hl-dec}

## 트러블슈팅

| 증상 | 원인 | 조치 |
|---|---|---|
| **규칙은 통과인데 응답이 안 옴**<br>방화벽 로그에는 초록 pass 가 찍힘 | **응답이 돌아오는 길에서 실종**<br>pf 가 WAN 규칙에 기본으로 붙이는 `reply-to` 가 "응답은 무조건 WAN 게이트웨이로"를 강제. 회선이 하나라 직행하면 될 응답이 공유기로 우회 | **Disable reply-to**<br>정상 라우팅으로 복귀. 손실 0% |
| **Grafana 가 Traefik 까지만 가고 타임아웃** | **정책 포트를 Service 값으로 적음**<br>Service 는 80 인데 파드는 3000 을 연다. NetworkPolicy 는 kube-proxy 가 주소를 바꾼 **뒤에** 파드 포트로 판정 | **3000 으로 교체**<br>같은 이유로 `targetPort` 이름 표기는 전부 숫자로 옮겨 적음 |
| **알림에 그림이 안 붙음**<br>렌더러 파드는 헬스체크를 계속 통과 | **일을 시킬 때만 죽음**<br>대기 88MiB 로 멀쩡히 살아 있고, 그리는 순간 591MiB. 상한 384MiB 가 피크의 65% 라 요청마다 OOMKill — 부르는 쪽에는 연결 끊김으로만 보임 | **상한을 피크의 130% 로**<br>요청은 대기값 기준으로 내려 스케줄 여유를 안 잠식 |
| **조회 컴포넌트가 전 네임스페이스 Secret 52개를 읽음**<br>MySQL root · ArgoCD 키 · 노드 조인 비밀번호 포함 | **차트가 만든 ClusterRole**<br>values 주석은 "감시 범위를 좁히면 RBAC 도 좁아진다"고 적고 있었는데 그 문장이 틀렸다 — 둘은 다른 값이 정한다 | **네임스페이스 Role 로 내림**<br>실제 쓰는 규칙만 남김. `kube-state-metrics` 는 수집 항목에서 `secrets` 제거 |
{:.hl-tbl}

## 결과

- **인터넷에 열린 포트는 2개입니다** — `443/TCP`(서비스) · `51820/UDP`(관리 터널). 그 밖은 공유기가 버립니다
- **파드 사이 통로를 16줄만 남겼습니다** — 나가는 방향도 함께 막아, 앱 파드에서 관측 저장소와 인터넷으로 못 나갑니다
- **관리 접근의 심사가 주소에서 키로 바뀌었습니다** — 출발지 주소는 보내는 쪽이 적는 값이고, 서명은 비밀키 없이 못 만듭니다
- **밖에서 재서 확인했습니다** — 공인 IP 로 직접 443 은 **타임아웃**, TLS 1.0·1.1 은 **거부**, 공개 첫 24시간 36,250건에 **차단 0%**

## 남은 것

- **`vpn` 이름 하나는 가릴 수 없습니다** — WireGuard 가 UDP 라 프록시를 못 켭니다. 조회하면 집 공인 IP 가 나오고, 그 주소에서 응답하는 것은 51820 하나입니다
- **관리 경로가 OPNsense 한 대에 몰려 있습니다** — 이 VM 이 내려가면 관리·격리망 인터넷·배포 알림이 함께 멈춥니다
- **밖에서 보는 프로브가 하루 10시간 40분은 감시 밖입니다** — 야간 예약 종료 시간대를 유지보수 창으로 잡아 둔 결과입니다
