## 왜 노트북이고, 왜 Proxmox인가

상시 켜 두는 서버라 **호스트 OS의 사정에 클러스터가 끌려가면 안 됐습니다.** Windows 위에 얹으면 업데이트 한 번에 세 노드가 같이 내려갑니다.
그래서 하드웨어 바로 위에서 도는 Type 1 하이퍼바이저로 정했고, 후보 중에서는 이렇게 갈렸습니다.

| 후보 | 탈락·선택 이유 |
|---|---|
| ESXi | 무료판에서 관리 기능이 막히고, 이 노트북 NIC를 잡지 못함 |
| 순수 KVM | 돌기는 하지만 VM을 관리할 도구를 직접 붙여야 함 |
| **Proxmox VE** | KVM 위에 관리 UI·백업·스냅샷이 얹혀 있고, 리눅스를 그대로 만질 수 있음 |

설치는 **외장 USB SSD**에 했습니다. 내장 NVMe의 Windows를 지우지 않고 공존시키려는 선택이고,
그 대가로 **USB가 빠지면 서버가 내려갑니다.** 이 홈랩의 물리적 제약이라 감수하고 시작했습니다.

## 기본으로 주는 것을 껐다

k3s는 네트워크·로드밸런서·인그레스를 기본으로 얹어 줍니다. 셋 다 끄고 직접 골랐습니다.

| 껐다 | 대신 | 그렇게 한 이유 |
|---|---|---|
| flannel | Calico | NetworkPolicy를 실제로 집행해야 했다 — 뒤에서 파드 간 통로를 잠그는 작업이 여기 달려 있다 |
| ServiceLB | MetalLB | 주소 풀을 내가 정해야 공유기 DHCP 대역과 겹치지 않는다 |
| 번들 Traefik | 직접 올린 Traefik | 인그레스 설정을 차트가 쥐고 있으면 엔트리포인트·미들웨어를 내 값으로 못 바꾼다 |

**대가는 부트스트랩 순서입니다.** CNI가 없으면 노드가 `NotReady`로 서 있고, 그 상태에서 무엇을 먼저 올릴지를 직접 정해야 합니다.
순서에 의존이 있는 것들(CNI·인증서 발급기·봉인 해제기·GitOps 도구)만 손으로 올리고, 나머지는 전부 GitOps가 가져가도록 경계를 그었습니다.

## 디스크를 워크로드마다 잘랐다

한 볼륨을 여러 워크로드가 나눠 쓰면, 용량이 찼을 때 **누가 채웠는지가 지표에 남지 않습니다.**
파일시스템 사용량은 파일시스템 단위로만 보고되기 때문입니다. 그래서 디스크 하나 = 파일시스템 하나 = PV 하나로 맞췄습니다.

```
k3s-1 (db)    MySQL 20G · Kafka 30G · Mimir WAL 5G
k3s-2 (obs)   Kafka 30G · Mimir WAL 5G · Loki WAL 5G · Tempo WAL 5G
k3s-3 (obj)   Kafka 30G · Mimir WAL 5G · MinIO 100G
```

노드마다 라벨을 붙여 디스크 배치와 파드 배치를 짝지었고, 디스크는 시리얼로 지목해 붙였습니다 —
재부팅 때 장치 이름 순서가 바뀌어도 같은 디스크가 같은 자리에 붙습니다.

## kubelet 몫은 짐작 대신 실측했다

k3s는 컨트롤플레인이 파드가 아니라 **프로세스 하나**로 돕니다. 쿠버네티스 입장에서는 집계 밖이라,
예약해 두지 않으면 노드가 가진 메모리를 전부 파드에 내줄 수 있다고 신고합니다. 그 상태로 메모리가 모자라면
커널이 고르는 희생자에 **etcd를 품은 k3s 자신**이 들어갑니다.

처음에는 1Gi로 잡았다가, 파드가 다 올라온 상태에서 실제 사용량을 재 보니 노드마다 1.5–1.8Gi였습니다. 2Gi로 올렸습니다.

## 막힌 곳 — 클러스터 안은 되는데 밖에서만 안 닿았다

```
증상   클러스터 안에서는 전부 통신되는데 데스크탑에서만 노드에 못 닿음
진단   범위를 반씩 좁혀 업링크를 특정 → 링크는 살아 있는데(carrier yes) ARP가 실패
       dmesg 에 Hardware Unit Hang 34회
원인   Intel e1000e NIC 의 TCP 오프로드 결함
조치   해당 오프로드를 끄고, 재부팅에도 유지되도록 인터페이스 기동 스크립트에 고정
```

처음에는 udev 규칙으로 붙이려다 실패했습니다 — 규칙이 걸리는 순간에는 인터페이스 이름이 아직 바뀌기 전이라,
**조건이 성립하는 시점이 존재하지 않았습니다.** 적용 시점을 인터페이스 기동 뒤로 옮겨 해결했고,
"지금 적용됐나 / 올릴 때마다 적용되나 / 재부팅을 넘기나"를 각각 확인했습니다.
